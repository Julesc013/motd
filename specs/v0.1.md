# v0.1 scope and acceptance contract

## Goal

Turn the existing workshop dashboard into a reusable Linux MOTD generator and manager. Workshop and home-lab variations come from configuration over one existing Bash engine. Ship a single downloadable Python configurator that can emit a standalone Bash dashboard or static public text.

This document defines the small first-version boundary. An item here is an acceptance requirement, not evidence that a release or every host integration has been validated.

## Accepted

| Area | v0.1 contract |
|---|---|
| Configurator | Python 3.11+; standard library only; one downloadable `motd.py`. |
| Runtime | `runtime/motd.bash` remains canonical and is embedded verbatim in the configurator. Generated Bash output runs independently of Python and the repository. Its inherited requirements include Linux/procfs, Bash 4.3+, and GNU `timeout`. |
| Configuration | TOML presets `workshop`, `home-lab`, and `public-console`; validated effective settings; generated Bash metadata can recover supported configuration. Static exports retain separate recipes. No guessed settings from arbitrary shell source or preservation of arbitrary TOML comments. |
| Opening workflow | Create, install, reconfigure, inspect/audit, repair, uninstall, and rollback. The action comes before detailed configuration questions. |
| Interactive targets | `--target shell --scope user|system`, with explicit interactive/TTY guards and `--audience all|ssh|local`. System defaults cover Bash login startup; non-login system integration needs an explicit host-appropriate `--shell-file`. |
| Preauthentication targets | `issue` and `ssh-banner`, generating static literal public notices without dashboard hooks or live private data. Imported static artifacts are already serialized bytes and retain their existing escape semantics. |
| Preview and custom commands | Default demonstration preview; `--live` collects local data. Both suppress before/after argv hooks for generated recipes. Recognized artifacts are rebuilt for preview. Explicit opaque-code execution with `--live --trust-artifact` can have side effects. Shell evaluation requires an explicit invocation such as `bash -c`. |
| Installation | Read-only `plan`; `install` shows its plan and asks before applying, with `--yes` for explicit noninteractive application. Explicit owned paths or marked regions, recorded state, and transaction archives containing configuration and outputs. Existing destination parents are required. |
| Existing scripts | Inspect without execution; recover recognized metadata; installation of any imported Bash bytes requires `--trust-artifact` and a recorded SHA-256. |
| Recovery | `repair --name NAME` uses the current complete installation manifest across upgrades/no-ops/rollback lineage; `--transaction ID` remains available. Repair restores missing owned files and preserves modified files. Rollback inverses a completed transaction, rejecting later ownership/drift. Recover reverses an interrupted apply. Archives contain output, journal, binary before/after images, and the recipe when one exists. Opaque imports do not get an invented recipe. |
| Recovery limits | Bytes, mode, UID, and GID are preserved; ACLs/xattrs are not. File replacements are atomic individually, not as a multi-file transaction. A project lock cannot exclude a noncooperating external writer. |
| Delivery | Source repository plus single-file configurator and generated output. No dependency installation or update checks during normal login display. |

## Acceptance evidence

The first release must demonstrate the following behavior on its stated Linux/Bash environment:

1. A preset can be configured, previewed, and generated; the result works without the configurator or source tree present.
2. Workshop and home-lab presets exercise the same runtime, and the packaged runtime matches its canonical source. Historical imports remain under `reference/` with provenance.
3. Settings and command arguments containing spaces, quotes, and shell metacharacters retain their intended data boundaries. Explicit shell commands execute only through the chosen hook path.
4. Generated-recipe previews do not run hooks, and inspect/audit does not run the inspected script. Opaque execution requires the explicit live/trust combination and reports that side effects cannot be suppressed.
5. Interactive eligible sessions display as configured; noninteractive remote commands remain quiet. The SSH filter and terminal guard are exercised independently.
6. Static targets contain the configured public text and do not execute the dashboard. Actual agetty/OpenSSH integration claims require host-specific evidence.
7. Plans describe the applied files. Repeated installation, local changes, repair, uninstall, and rollback preserve unrelated content and report conflicts.
8. A generated Bash output can recover its configuration; a static output retains a separate recipe. An arbitrary import retains its bytes and fingerprint without an invented editable configuration.

Performance claims must identify the host, configuration, command, and measurement method. Preserve metric definitions and enabled coverage when comparing runtime revisions. This version does not claim a measured latency on every target machine.

## Deferred

- A native Go or Rust runtime rewrite, general plugin ABI, arbitrary layout language, or separate renderer.
- A web designer, hosted gallery, marketplace, account service, or remote configuration service.
- APT/RPM repositories, automatic self-updates, and release-signing infrastructure presented as already available.
- Zsh/Fish-specific integration, PowerShell, Windows, DOS, macOS/BSD support, and non-shell status surfaces.
- Parsing arbitrary Bash into editable settings or preserving all comments and formatting in arbitrary TOML documents.
- Dynamic preauthentication telemetry, privileged collection services, and persistent background daemons.

These are possible later decisions, not hidden requirements for finishing v0.1.

## Open release decision

Select the project license and verify provenance before assigning redistribution terms. Do not silently inherit a license from an inspiration project or add one by assumption.
